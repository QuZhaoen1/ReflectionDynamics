# 动作概率测量问题（未修复）

运行版本 `refldyn/backend.py::action_probability` 将 prompt 编码后，拼接单独编码的 `COMMIT` 和 `REFLECT`，分别累加 token log likelihood，再在两个字符串间归一化。它得到的是两条特定 token 路径的相对分数，而非完整自然动作事件的概率。

本次自然输出常见额外前导空格。Qwen tokenizer 对 `COMMIT` 编码为 `[8696, 18330]`，` COMMIT` 为 `[83230]`；`REFLECT` 为 `[5996, 3965]`，` REFLECT` 为 `[38029, 3965]`。prompt 以 `ACTION: ` 结束，token 边界还需按实际自回归生成前缀处理，不能简单把完整拼接文本重新编码当作修复。原方法未覆盖这些自然生成路径，也没有严格定义动作结束边界。评估生成还使用 temperature=0.7/top_p=0.95，与原始 logits 的分布不同。

因此约 99.7% 的归一化字符串分数与 55.02%→31.88% 的实际采样 REFLECT 比例并非同一个量。后者是每状态一次采样得到的总体频率，不能替代每状态稳定概率或用于声称概率校准。

本次归档排除 `p_reflect`、`reflection_propensity`、`selectivity`、`policy_utility`、`frequency_matched_random`、`oracle_regret` 及依赖这些概率的跨 checkpoint 矩阵。原始错误口径文件仍留在服务器供追溯，不在有效结果表中展示。自然采样正确性、格式率、强制反思纠错/损害以及独立重试统计不依赖这段 likelihood 计算，仍可作为带有限样本限制的描述性结果。

后续修复需要明确：动作事件包含哪些前导空白和结束形式、采用原始模型分布还是实际解码分布、如何处理无效动作，以及如何验证事件概率与采样频率一致。在小型可枚举 tokenizer/分布测试和真实 tokenizer 边界测试通过后，先对小批真实状态做校准检查，再重算全量。仅给两个字符串加空格不构成完整验证。

这次上传保留历史补丁以精确追溯运行，没有擅自改变估计量或把尚未验证的新计算伪装成已修复结果。修复后可复用已有强制反思/重试结果，无需仅为这个测量问题重新训练。
